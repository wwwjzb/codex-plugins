# 妙响歌曲创作向导

## 核心原则

- 本技能用于妙响（Sway5.5）歌曲策划。最终输出必须可直接粘贴到妙响使用，默认以华语 R&B 场景为主。
- 问卷共 8 轮，固定顺序。每轮先依据上一轮答案从参考库筛选，展示**至少 5 个选项**；末尾始终提供「以上都不是，自定义补充」。
- 每轮选项必须因上一轮答案而变化，不得复用固定菜单。
- 用户自定义答案时：记录原话，映射到最接近的既有分支继续后续轮次；无法映射时以「主题 + 情绪」为锚点继续。
- 纯音乐处理：用户在任意轮次声明「纯音乐」时，第 4 轮（人声）与第 8 轮（歌词部分）标记为不适用，第 8 轮结构锁定「纯音乐 / Instrumental」；歌词框只写 `纯音乐`，风格描述不得包含任何主唱、唱法或和声人声描述。
- 一次只问一轮。不要提前展示后续轮次，不要替用户做选择。
- 硬性约束：不指定真实艺人姓名；歌词必须原创；多音字按「改写整句 → 换词 → 同音字」顺序处理；风格描述禁用高频打击与宽频噪声词汇；「明亮」按音色与混音清晰度理解，不靠高频或镲片。
- 主题锚定后**直接生成歌词草稿**（按 lyric-guide.md 规则、使用歌曲语言），后续轮次基于草稿调整；关键轮次试听与最终成品一律使用当前歌词，不依赖模型自动写词。
- 第 6 轮律动选项只从所选风格的「律动方案」出，禁止跨风格鼓型混入（trap 808 / 2-step / funk 十六分等）；Trap-Soul 是唯一允许受控闭镲与 Clap 的风格，鼓组必须逐拍写清（Kick 1 拍 / Snare 3 拍 / 禁 2、4 反拍）。

## 问卷流程（8 轮）

| 轮次 | 决策内容 | 依据 | 参考文件 |
| --- | --- | --- | --- |
| 1 | 主题锚定：已给主题则确认一句话概念；未给则出主题菜单（≥6 项） | 用户输入 | theme-bank.md |
| 2 | 核心曲风（≥5 项） | 主题 | style-bank.md |
| 3 | 情绪基调（≥5 项） | 主题 + 曲风 | style-bank.md |
| 4 | 主唱人声（≥5 项：音色/音域/唱法/禁用） | 曲风 + 情绪 | style-bank.md |
| 5 | 核心编配/乐器（≥5 项组合） | 曲风 | style-bank.md |
| 6 | 律动与速度（≥5 组方案：鼓组 + 速度/拍号/重拍，含高频安全替代） | 曲风 + 编配 | style-bank.md, sound-guide.md |
| 7 | 制作质感与效果器（≥5 项质感/混音方向，附 Sway5.5 安全做法） | 情绪 + 人声 | sound-guide.md |
| 8 | 歌词与结构（基于第 1 轮歌词草稿选择歌词风格/叙事 + ≥5 项结构；段落发展在最终组装时按结构模板给出） | 情绪 + 曲风 | lyric-guide.md, style-bank.md |

### 每轮交互规范

1. 用编号列出选项（如 `1. 深夜都市`），并给每个选项一句话说明。
2. 选项末尾固定追加 `N+1. 以上都不是，自定义补充`。
3. 提示用户「回复编号，或输入你自己的答案」。
4. 用户选编号 → 记录选项名与完整配置（音色、禁用项、速度等）。
5. 用户自定义 → 记录原话，说明映射到的分支（如「我按 当代R&B-温柔低男声 分支继续」），然后进行下一轮。

## MiniMax 试听预览（参数试听 + 成品择优）

预览用来听「每一轮选择带来的听觉变化」；最终成品从零生成完整版并按需择优。**已知限制：翻唱模型保留原编曲，无法按参数加乐器/改律动（2026-08-14 实测，锚点与「要求加乐器」的翻唱版听感基本一致）**，因此参数试听一律用从零生成，翻唱只用于成品风格变体。

### 关键轮次定义

- 第 1 轮（主题）、第 2 轮（曲风）、第 3 轮（情绪）、第 4 轮（人声）、第 5 轮（编配/乐器）、第 6 轮（律动与速度），共 6 个关键轮次。
- 若用户已声明「纯音乐」，第 4 轮（人声）不适用，跳过该轮预览；第 5 轮（编配）仍生成。
- 用户自定义答案时同样生成预览（用映射后的分支配置组装 prompt）。

### 三段式提示词（Structured Caption，MiniMax 官方推荐）

- 每轮预览 prompt = 「三段式结构化描述」，按 `references/minimax-caption.md` 模板组装；**写完整英文句子（约 250–450 词），不用逗号标签堆砌**：
  1. Global Metadata：歌曲语言 + 主题一句话 + 曲风家族/子类 + BPM/拍号/调性 + 情绪推进 + 聆听场景 + 制作质感
  2. Vocal Details：人声性别/音色/唱法 + 和声/伴唱/人声效果
  3. Arrangement：主/次乐器 + 段落级乐器演变 + 律动/贝斯/打击 + 织体与空间效果
- DNA 锚定信息固定不变，放进 Global Metadata（如「English broken-love song, contemporary R&B, late-night bedroom, warm and loose」），保持试听同源感。
- 已积累参数按 主题 → 曲风 → 情绪 → 人声 → 编配 → 律动/速度 顺序逐轮映射到对应小节；每轮只追加新选择，保留之前全部，总长 ≤2000 字符。
- 歌词永远不写进 prompt：通过 `--lyrics` 单独传入；结构标签只用官方 14 个（`[Intro] [Verse] [Pre Chorus] [Chorus] [Interlude] [Bridge] [Outro] [Post Chorus] [Transition] [Break] [Hook] [Build Up] [Inst] [Solo]`），**不用 [Final Chorus] 或带连字符的 [Pre-Chorus]/[Post-Chorus]**；末段副歌用 [Chorus] + 括号指令/Ad-lib 表达升级。
- 乐器词库只用 MiniMax 官方可识别写法（808 sub-bass、rolling triplet hi-hats、trap percussion、Rhodes piano、electric piano (Rhodes-style)、plucked synth、synth pad 等）；**禁止把妙响式安全替代词（闷 Snare、闷 Rim、木质 Tick、短 Stab 替代 Hat）写进 MiniMax prompt**。
- 官方限制（MiniMax Music 3 文档）：这些控制是**生成式引导而非严格保证**，tempo/key/乐器/结构可能不完全匹配；三段式只能提高命中率。

### 生成流程

1. 第 1 轮（主题锚定）：用户确认主题与歌曲语言后，**先生成歌词草稿**——按 `lyric-guide.md` 的段落标签、每段 4-8 行、原创与多音字检查规则，用歌曲语言写完整结构草稿（Intro / Verse / Pre-Chorus / Chorus / Bridge / Outro），展示给用户确认或按意见修改；然后生成哼唱方向试听（可选，`--lyrics` 传哼唱衬词）+ 主题参数试听（从零生成，30 秒，`--lyrics` 传草稿歌词）。
2. 关键轮次试听（从零生成，wav，30 秒，错开截取）：

   ```
   <python> <skill目录>/scripts/preview.py --prompt "三段式结构化描述" --offset <错开秒数> --tag r<N> --out "D:\AI MUSIC\previews"
   ```

   - 错开起始点：r1=0s、r2=15s、r3=30s、r4=45s、r5=60s、r6=75s（时长不足时脚本自动收回）。
   - 歌词：关键轮次试听一律使用当前歌词（草稿或其修改版，传 `--lyrics`），不再依赖自动写词；纯音乐 → `--instrumental`。
3. 最终成品（从零生成完整版）：
   - 用完整结构化歌词（草稿经各轮调整后的最终版；含重复副歌、预副歌、哼唱衬词，尽量接近 3500 字符上限）+ 全部参数 + 最终风格描述，`--seconds 0` 保留完整。
   - 生成 2-3 版听感择优；若时长 <60 秒，免费重新生成（最多 3 次）取最长。
4. 翻唱（可选，成品变体）：成品定稿后，如需「更松弛 / 更舞池 / 换声线」等风格变体，用 `--cover-base <成品>` + 变体风格描述 + 精简歌词（≤1000 字符）生成；**翻唱不改编曲**，只做风格微调，交付时明确告知用户这一点。

### 时长经验（实测）

- 从零生成输出时长由歌词完整度决定：短占位歌词约 30 秒，完整结构化歌词可到 3 分钟以上（2026-08-13 实测 3:35）。需要长成品就用完整结构化歌词直接生成。
- 翻唱输出时长跟随参考音频，且每翻一次会小幅缩水（实测锚点 3:10 → 第六轮翻唱 2:36，全程缩约 18%）；翻唱只用于变体，不作为长度来源。

### 密钥与安全

- API Key 通过环境变量 `MINIMAX_API_KEY` 或 `~/.codex/miao-song-planner/config.json` 的 `api_key` 字段提供。
- **严禁**把 API Key 写进 SKILL.md、参考文件或任何提交到 GitHub 的文件。

### 预览输出与清理

- 试听文件：wav，30 秒，按轮次错开起始点，保存在 `D:\AI MUSIC\previews\`，命名 `r<轮次>_<时间戳>.wav`。
- 成品：wav 或 mp3 完整版，命名 `final_<时间戳>`。
- 完整曲目生成后，必须询问用户「是否保留本次问卷产生的试听文件」：
  - 用户选择保留 → 列出本次试听文件清单与路径，继续。
  - 用户选择不保留 → 先展示本次问卷生成的试听文件清单，经用户确认后删除；**始终保留成品 `final_*` 与创作方案**。
  - 删除范围仅限本次问卷会话生成的预览文件；删除前必须展示清单并获得明确确认。

## 最终方案组装

问卷 8 轮结束后，按 `output-template.md` 一次性输出完整方案，包含 6 个部分：

1. 歌名：2-3 个候选 + 推荐 1 个。
2. 歌词框：完整歌词，使用英文段落标签与分段指令（`[Verse 1][soft Rhodes chords, ...]`），每段 4-8 行，段落间空行，即兴/旁白用圆括号，Hook 完整重复 2-3 次；交付前逐行做多音字检查。纯音乐作品写「纯音乐」。
3. 风格描述框：可直接粘贴的段落，顺序为 曲风/速度 → 调性/情绪 → 人声 → 乐器与律动 → 段落发展 → 混音空间 → Sway5.5 禁用清单。
4. 参数建议：人声性别、风格权重、参考音频权重（无参考音频时注明不适用）、创意发散程度，各给一句理由。
5. 创作蓝图：BPM/拍号/预计小节数/预计时长、调性、旋律轮廓、副歌四句模板与 Flow 蓝图、和声方向、前三秒抓耳入口、副歌三次回归矩阵。
6. 试听检查清单：按 sound-guide.md 与 output-template.md 给出生成后核对项。

## 歌曲归档（问卷全部完成并生成成品后）

完整曲目生成并处理完「试听保留/删除」询问后，执行归档：

1. 询问用户：给这首歌的归档文件夹起个名字（例如歌名《Dance With the Tide》）。
2. 在 `D:\AI MUSIC\songs\` 下创建 `<用户命名>` 文件夹；清洗非法字符（`\ / : * ? " < > |`），重名时追加 `-2`、`-3` 序号。
3. 把成品 `final_*` 移入该文件夹；若用户选择保留试听，把本次问卷生成的试听文件（`r<轮次>_*.wav`、`demo_*.wav`、哼唱版等）一并移入。
4. 写入三个文本文件（UTF-8）：
   - `<命名>_lyrics.txt`：歌词框完整内容
   - `<命名>_style.txt`：风格描述框完整内容
   - `<命名>_plan.md`：完整创作方案（六部分）
5. 向用户汇报归档文件夹路径与文件清单。

## 参考文件导航

- `references/theme-bank.md`：第 1 轮主题菜单、主题→曲风映射、自定义主题锚定规则。
- `references/style-bank.md`：第 2/3/4/5/6/8 轮。15 类 R&B 风格库与跨轮分支映射；用户选定曲风后只读取该风格的分节。
- `references/lyric-guide.md`：第 8 轮、歌词撰写与多音字检查。
- `references/sound-guide.md`：第 6/7 轮、风格描述撰写、高频噪声与明亮度规则。
- `references/minimax-caption.md`：MiniMax Music 3 官方三段式提示词模板（Global Metadata / Vocal Details / Arrangement）与问卷参数映射规则。
- `references/output-template.md`：最终方案组装模板。
